# План: деконструкция монтажа референса и база знаний для AI-монтажёра (HyperFrames)

**Цель:** научиться логике дорогого монтажа на референсе `reference/ref01.mp4`: какие приёмы использованы, с какими параметрами и **почему именно они именно здесь**. Результат — база знаний: посекундная таблица (Модуль 1), дизайн-система и дерево решений (Модуль 2), системный промпт агента (Модуль 3) и конфиг стиля (Модуль 4). По этой базе Claude Code сможет монтировать YouTube long-form экспертные видео 16:9 в той же стилистике через HyperFrames.
**Где выполнять:** облако (анализ, скрипты, документы).
**Ничего не монтировать и не рендерить без прямой команды пользователя.** В этом плане монтажа нет, только анализ и база знаний.
**Критерий готовности:** в `kb/` лежат 4 модуля. Обратная проверка (Фаза 6): дерево решений, применённое «вслепую» к транскрипту референса, предсказывает фактически использованные приёмы и их места; совпадение измерено и записано.

## Исходные данные и решения (зафиксировано)

- **Референс:** `reference/ref01.mp4`. 121,4 с, 1280×720, 29,97 fps (2997/100), H.264 + AAC 44,1 кГц стерео. Язык речи русский.
- **Целевой формат:** YouTube long-form, экспертный контент, 16:9, 1920×1080, **30 fps**. Пиксельные значения, измеренные на 720p, умножаются на 1,5. Длительности измеряются в кадрах референса (29,97 fps), переводятся в мс и затем в кадры при 30 fps.
- **SFX:** библиотеки нет. В конфиге и правилах звуки только описываются: тип, длительность в мс, частотный профиль, уровень относительно голоса, точка атаки.
- **Шрифт:** если гарнитура референса платная, подобрать бесплатный аналог (Google Fonts или другой с открытой лицензией) и указать, чем он отличается.
- **Движок монтажа:** HyperFrames (HeyGen, Apache 2.0). Позже возможна адаптация под Remotion, поэтому все анимации описываются независимо от движка: кадры, мс, `cubic-bezier(x1,y1,x2,y2)`, px, %.
- **Что известно о HyperFrames:**
  - композиция — это HTML с `data-composition-id`, `data-width` и `data-height`;
  - клипы задаются через `data-start`, `data-duration`, `data-track-index`;
  - анимации пишутся на GSAP / CSS / WAAPI / Lottie, таймлайны регистрируются в `window.__timelines`;
  - звук можно сводить через `<hf-audio-group>`;
  - CLI: `npx hyperframes init | preview | render | lint | check`;
  - нужны Node 22+ (в контейнере v22.22.0) и FFmpeg (установлен);
  - скиллы для Claude Code: `claude plugin marketplace add heygen-com/hyperframes`, затем `claude plugin install hyperframes@hyperframes`.
- **Ограничения анализа** (в таблицах отмечать колонкой «уверенность»):
  - видео я вижу только как кадры, звук — только как транскрипт и спектральный анализ;
  - тип SFX и кривые easing — оценки по данным, а не исходные значения;
  - шрифт определяется на глаз.
- **Архивов и файлов пользователя нет**, работаем только с референсом.
- **Экономия токенов:** не смотреть отдельные кадры подряд. Только контакт-листы (3×3, тайлы 640×360, таймкод на каждом тайле) и точечные кропы на участках анимаций.

## Фаза 1 — Подготовка данных
- [x] `scripts/cuts.py`: склейки по ffmpeg scene score (порог 0,10, локальный максимум, разнос ≥ 6 кадров) → `analysis/cuts.csv`, `shots.csv`, `scene_scores.csv`. Движение → `motion.csv`. Влёты графики и плавные переходы (разница кадров i−5 / i+5) → `events.csv`.
- [x] `scripts/transcribe.py`: **вместо Whisper — GigaAM v2 (русская RNN-T) через sherpa-onnx + Silero VAD**, потому что huggingface.co закрыт сетью (403). Модели качаются из GitHub-релизов `k2-fsa/sherpa-onnx` в `/home/user/models` (вне репо, скрипт скачает сам). Результат: `analysis/transcript.json` (слова с таймкодами, шаг ~40 мс), `.srt`, `.txt`. Пунктуации нет.
- [x] `scripts/audio.py`: онсеты, RMS, центроид, полосы low/mid/high → `analysis/onsets.csv`, огибающие с шагом 100 мс → `bands.csv`.
- [x] `scripts/sheets.sh START END FPS NAME [COLS ROWS TILE_W]`: контакт-листы с таймкодом `t` и номером кадра на тайле. `scripts/cut_sheet.sh`: пары «до | после» для каждой склейки.
- [x] `scripts/run_all.sh`: вся фаза одной командой. Зависимости: `pip install sherpa-onnx librosa soundfile`.
- **Проверка:**
  - склейки сверены по `analysis/sheets/cuts_*.jpg`: настоящие склейки, punch-in/out и середины световых переходов;
  - транскрипт читается (тема: лидогенерация из Telegram-чатов);
  - в `onsets.csv` 619 онсетов; `run_all.sh` отрабатывает целиком (~1 мин), `analysis/` весит 3,6 МБ.
- **Итог:**
  - 28 склеек, 29 планов, ASL 4,19 с, медиана 3,24 с (мин 0,57, макс 9,08);
  - 20 из 28 склеек совпадают с аудио-онсетом в пределах ±2 кадров;
  - в `events.csv` 41 событие, из них ~10 не у склеек: это влёты графики, их нужно разобрать в Фазах 2–3.
- **Замечания для Фаз 2–3:**
  - детектор SFX шумный (108 кандидатов): в полосе <150 Гц всё время стоит музыкальная подложка ~25 dB, поэтому смотреть онсеты только в окнах графических событий;
  - номер `f` на тайлах `cut_sheet.sh` — номер в выборке, а не кадр ролика; верное время — второе число.
